# 09 — Authentication & Authorization

[← Back to Index](index.md)

## Summary

- **Authentication:** stateless **JWT** bearer tokens (HS256). Two login endpoints: OAuth2 form (`/auth/login`) and JSON (`/auth/login-json`).
- **Password storage:** **bcrypt** hashing (`src/utils.py`).
- **Authorization:** **role-based access control (RBAC)** via the `RoleChecker` dependency. Roles: `ROLE_USER`, `ROLE_ADMIN`.
- **Account recovery:** email **OTP** flow (forgot-password → verify-OTP → reset).

## Password hashing

```python
def hash_password(password: str) -> str:
    return bcrypt.hashpw(password.encode("utf-8"), bcrypt.gensalt()).decode("utf-8")

def verify_password(password: str, hashed_password: str) -> bool:
    return bcrypt.checkpw(password.encode("utf-8"), hashed_password.encode("utf-8"))
```

- Uses the `bcrypt` library directly (the commented-out `passlib` `CryptContext` was deliberately replaced — see git history `feat(auth/user): ... switch to bcrypt`).
- A fresh per-password salt is generated by `bcrypt.gensalt()`.

## JWT issuance

```python
def create_access_token(data: dict, expires_delta=None):
    to_encode = data.copy()
    expire = datetime.now(UTC) + (expires_delta or timedelta(minutes=ACCESS_TOKEN_EXPIRE_MINUTES))
    to_encode.update({"exp": expire, "iat": datetime.now(UTC)})
    return jwt.encode(to_encode, JWT_SECRET_KEY, algorithm=ALGORITHM)
```

- Payload on login: `{"sub": email, "name": name, "iat": ..., "exp": ...}`.
- `ALGORITHM = HS256`, `ACCESS_TOKEN_EXPIRE_MINUTES = 360` (6 hours), both from `config.yml` `Security`.
- `JWT_SECRET_KEY` resolves from env first (`os.getenv("JWT_SECRET_KEY")`), then `config.yml`.

## JWT validation (`get_current_user`)

```python
oauth2_scheme = OAuth2PasswordBearer(tokenUrl="/auth/login")

async def get_current_user(token = Depends(oauth2_scheme)):
    payload = jwt.decode(token, JWT_SECRET_KEY, algorithms=[ALGORITHM])  # JWTError -> 401
    email = payload.get("sub")                                          # missing -> 401
    user = await users_collection.find_one({"email": email})            # None -> 404
    return user
```

Every protected route depends on this. The **full user document** (including `role`) is attached as `current_user`, so routes can use `current_user["_id"]`, `["role"]`, etc.

## Authorization (RBAC)

```python
class RoleChecker:
    def __init__(self, allowed_roles: list[str]):
        self.allowed_roles = allowed_roles
    def __call__(self, current_user = Depends(get_current_user)):
        if not any(role in self.allowed_roles for role in current_user.get("role", [])):
            raise HTTPException(403, detail=f"... Required: {self.allowed_roles}")
        return current_user
```

Usage:
```python
@router.get("/admin-only")
async def admin_only_route(admin_user = Depends(RoleChecker(["ROLE_ADMIN"]))):
    ...
```

- `RoleChecker` is a **parameterized dependency** (an instance is created per-route). It composes on top of `get_current_user`, so a 401 (bad token) is raised before any role check.
- **Role assignment at signup:** if the requested role list contains `ROLE_ADMIN`, the user is stored with `["ROLE_USER","ROLE_ADMIN"]`. This means **any client can self-register as admin** — see the hardening note below.

## Login flows

### OAuth2 form (`POST /auth/login`)
Uses `OAuth2PasswordRequestForm` (`username` = email, `password`). This is the flow Swagger's **Authorize** button uses. Returns `{access_token, token_type:"bearer"}`.

### JSON (`POST /auth/login-json`)
Accepts a JSON `UserLogin` body. Returns `{access_token}` (no `token_type`). Intended for SPA/mobile clients.

### Logout (`POST /auth/logout`)
Validates the token and returns success, but does **not** revoke it. With stateless JWTs there is no server-side session; the client should discard the token. To support true revocation you'd need a denylist or short-lived tokens + refresh tokens.

## Password reset flows

### Authenticated change (`PUT /auth/reset-password`)
Verifies `old_password` against the stored hash, then updates to the new hash.

### Forgot-password OTP (email)

```mermaid
sequenceDiagram
    participant C as Client
    participant API as user_router
    participant DB as users
    participant SMTP as Gmail SMTP

    C->>API: POST /auth/forget-password {email}
    API->>DB: find_one({email})  (404 if none)
    API->>API: otp = generate_otp(); expiry = now+5min
    API->>DB: $set {otp, otp_expiry}
    API->>SMTP: send_otp_email(email, otp)
    API-->>C: 200 OTP sent  (or 500 on failure)

    C->>API: POST /auth/verify-otp-reset-password {email, otp, new_password}
    API->>DB: find_one({email})
    API->>API: validate otp present, matches, not expired
    API->>DB: $set hashed_password; $unset otp, otp_expiry
    API-->>C: 200 Password reset successfully
```

- OTP is a 6-digit numeric code, valid **5 minutes**.
- Sent via Gmail SMTP (STARTTLS, port 587) using `SENDER_EMAIL` / `SENDER_PASSWORD` (a Gmail app password).
- After a successful reset, `otp` and `otp_expiry` are removed from the user document.

## Token lifecycle diagram

```
login ──► JWT(sub,name,iat,exp=+6h) ──► client stores token
   │
   └─► each request: Authorization: Bearer <jwt>
                         │
                         ├─ valid + not expired ──► get_current_user ──► route
                         ├─ expired/garbled ─────► 401 Invalid or expired token
                         └─ user deleted ────────► 404 User not found
```

## Security hardening recommendations

These are **not** currently implemented; see [14 — Security](14-security.md) for the full list.

1. **Restrict admin self-assignment** — signup should not let arbitrary clients request `ROLE_ADMIN`.
2. **Store `JWT_SECRET_KEY` only in env**, never commit it; ensure a strong (≥32 byte) random value.
3. **Add a unique index on `users.email`** to prevent race-condition duplicates.
4. **Rate-limit** login, signup, forgot-password, and verify-OTP endpoints.
5. **Hash/limit OTP attempts** and lock after N failures.
6. Consider **refresh tokens** + short access-token TTL, and a revocation list for logout.
